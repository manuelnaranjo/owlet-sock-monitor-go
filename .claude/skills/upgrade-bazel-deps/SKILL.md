# Upgrade Bazel and bzlmod Dependencies

## Objectives

Upgrade the Bazel toolchain and all module dependencies to their latest stable releases:

1. Update `.bazelversion` to the latest stable Bazel release
2. Update all `bazel_dep` versions in `MODULE.bazel`
3. Update the Go SDK version in `MODULE.bazel` (if using `rules_go`)
4. Bump the `go` directive and all dependencies in `go.mod`, regenerate `go.sum`
5. Regenerate any auto-generated config files (e.g. `tools/preset.bazelrc`)
6. Verify the entire repo builds successfully

## Finding Latest Versions

Use web search or fetch the following sources:

- **Bazel**: https://github.com/bazelbuild/bazel/releases (pick latest non-RC tag)
- **Bazel Central Registry modules** (rules_go, gazelle, bazelrc-preset.bzl, tar.bzl, buildifier_prebuilt, etc.): https://registry.bazel.build/modules/<MODULE_NAME>
- **Go**: https://go.dev/dl/ (pick latest stable `go1.X.Y`)
- **Go modules** (prometheus, etc.): GitHub releases pages or `go get -u`

## Step-by-Step Process

### 1. Update `.bazelversion`

Replace the content with the new version string (e.g. `9.0.2`). Do not use wildcard versions like `8.x` — pin to an exact version.

### 2. Update `MODULE.bazel`

For each `bazel_dep`, update the `version` field to the latest available in BCR. Also update any version strings passed to extensions (e.g. `go_sdk.download(version = "...")`).

```python
# Before
bazel_dep(name = "rules_go", version = "0.57.0")
bazel_dep(name = "gazelle",  version = "0.45.0")

# After
bazel_dep(name = "rules_go", version = "0.60.0")
bazel_dep(name = "gazelle",  version = "0.50.0")
```

### 3. Update `go.mod`

Update the `go` directive to the new Go version, then run:

```
go get -u ./...
go mod tidy
```

`go get -u` upgrades all direct and transitive dependencies to their latest compatible versions. `go mod tidy` removes unused entries and regenerates `go.sum`.

### 4. Regenerate Auto-Generated Bazel Files

If the repo uses `bazelrc-preset.bzl`, regenerate `tools/preset.bazelrc` after bumping the dep:

```
bazel run //tools:preset.update
```

### 5. Verify

```
bazel build //...
```

Fix any build errors caused by breaking changes in upgraded modules.

## Notes

- Prefer exact version pins in `.bazelversion` over wildcards (`8.x`) — wildcards can pick up unexpected minor versions.
- When jumping a major Bazel version (e.g. 8→9), the `tools/preset.bazelrc` generated by `bazelrc-preset.bzl` must be regenerated — it contains version-specific incompatibility flags.
- `go get -u` only upgrades within the major version. For major version bumps (e.g. `v1` → `v2`) you must update import paths manually.
- After `go get -u ./...`, run `go mod tidy` to prune indirect deps that are no longer needed and add any new ones required by updated packages.
- The Bazel lockfile (`MODULE.bazel.lock`) is regenerated automatically on the next build after changing `MODULE.bazel` — no manual action needed.

## Learnings from Other Sessions

### Bazel 8 → 9 upgrade (owlet_monitor_go, April 2026)

- `bazelrc-preset.bzl` 1.4.0 → 1.9.2: the preset regeneration (`bazel run //tools:preset.update`) must be run **after** Bazel itself is upgraded, not before. Running it with the old Bazel version generates a preset for the wrong version.
- After a major Bazel version bump the server must restart. Bazel detects JVM flag differences and kills the old server automatically — this is expected and not an error.
- `go get -u ./...` on this project upgraded: `prometheus/common` (v0.66.1→v0.67.5), `prometheus/procfs` (v0.16.1→v0.20.1), `go.yaml.in/yaml/v2` (v2.4.2→v2.4.4), `golang.org/x/sys` (v0.35.0→v0.43.0), `google.golang.org/protobuf` (v1.36.8→v1.36.11). The main `prometheus/client_golang` dep was already at latest (v1.23.2).
- The `MODULE.bazel.lock` file does not need manual editing — Bazel regenerates it on the first build.
- Building with Bazel 9 after upgrading from Bazel 8 showed no breaking API changes in this project's BUILD files. The upgrade was transparent at the BUILD level.
